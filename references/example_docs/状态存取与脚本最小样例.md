# 状态存取与脚本最小样例

这份文档专门处理“什么时候该存状态”“什么时候才该上脚本”。

## 状态存取优先规则

- 需求如果是动作级持久化键值数据：
  - 默认优先 `sys:stateStorage`
- 需求如果只是本机当前动作自己保存一点配置、历史值、上次结果：
  - 仍然优先 `sys:stateStorage`
- 只有在明确要求跨设备、跨账号共享时：
  - 才考虑 `sys:clouddata`
- 不要把“存一点状态”默认实现成 `运行C#代码`。

## 状态存取：写入

```json
{
  "StepRunnerKey": "sys:stateStorage",
  "InputParams": {
    "type": { "VarKey": "", "Value": "saveActionState" },
    "key": { "VarKey": "", "Value": "存储的key" },
    "value": { "VarKey": "", "Value": "存储的内容" }
  },
  "OutputParams": {}
}
```

要点：

- `value` 写 `*NULL*` 表示删除该键对应的状态。

## 状态存取：读取

```json
{
  "StepRunnerKey": "sys:stateStorage",
  "InputParams": {
    "type": { "VarKey": "", "Value": "readActionState" },
    "key": { "VarKey": "", "Value": "存储的key" },
    "defaultValue": { "VarKey": "", "Value": "" },
    "inputIfEmpty": { "VarKey": "", "Value": "0" },
    "prompt": { "VarKey": "", "Value": "" }
  },
  "OutputParams": {
    "isSuccess": "out_isSuccess",
    "value": "value",
    "isEmpty": "out_isEmpty",
    "errMessage": "out_errMessage"
  }
}
```

要点：

- 若读取结果只用于后续是否回填配置，通常还要接一个“是否为空”的条件判断。
- 配置型动作优先在主流程前段统一读取，不要分散到多个分支里重复读取。

## 配置词典持久化模板

- 当前工作区已验证，配置词典可采用“直接存词典”或“先转 JSON 再存”两种成熟写法。
- 当需求是“多字段表单维护一组配置，下次运行继续用”时，推荐优先使用下面的结构：

```json
[
  {
    "StepRunnerKey": "sys:stateStorage",
    "InputParams": {
      "type": { "VarKey": "", "Value": "readActionState" },
      "key": { "VarKey": "", "Value": "config" },
      "inputIfEmpty": { "VarKey": "", "Value": "0" },
      "prompt": { "VarKey": "", "Value": "" }
    },
    "OutputParams": {
      "value": "configJson",
      "isEmpty": "configIsEmpty"
    }
  },
  {
    "StepRunnerKey": "sys:simpleIf",
    "InputParams": {
      "condition": { "VarKey": "", "Value": "$= {configIsEmpty} == false" }
    },
    "OutputParams": {},
    "IfSteps": [
      {
        "StepRunnerKey": "sys:comment",
        "InputParams": {
          "note": { "VarKey": "", "Value": "这里按当前已验证方案回填配置词典。可直接读入词典变量，或按既有案例使用 JSON 反序列化。" }
        }
      }
    ]
  },
  {
    "StepRunnerKey": "sys:stateStorage",
    "InputParams": {
      "type": { "VarKey": "", "Value": "saveActionState" },
      "key": { "VarKey": "", "Value": "config" },
      "value": { "VarKey": "", "Value": "$= JsonConvert.SerializeObject({configDict})" }
    },
    "OutputParams": {}
  }
]
```

要点：

- 这里展示的是结构模板，不是要求凡事都先上脚本。
- 若当前工作区案例已确认可直接把词典变量写进状态，也可以直接存词典。
- 若当前动作已经验证“状态文本直接读回词典变量”可用，优先沿用该成熟写法。
- 若只是想保存一两个简单值，没必要先包装成大词典。

## 保存后即停止的典型结构

- 设置入口、管理入口、维护入口通常采用：
  - 表单修改
  - `sys:stateStorage`
  - `sys:notify`
  - `sys:stop`
- 这是比“保存完继续跑主功能”更稳定的默认结构。

## 运行 C#：最小模板

- 只有在内置模块、表达式、文本插值明显不适合时才使用。

```json
{
  "StepRunnerKey": "sys:csscript",
  "InputParams": {
    "mode": { "VarKey": "", "Value": "normal" },
    "script": {
      "VarKey": "",
      "Value": "//.cs\r\npublic static void Exec(Quicker.Public.IStepContext context)\r\n{\r\n}\r\n"
    },
    "reference": { "VarKey": "", "Value": "" },
    "runOnUiThread": { "VarKey": "", "Value": "auto" },
    "enableCache": { "VarKey": "", "Value": "0" },
    "stopIfFail": { "VarKey": "", "Value": "1" }
  },
  "OutputParams": {
    "isSuccess": "out_isSuccess",
    "rtn": "rtn",
    "errMessage": "out_errMessage"
  }
}
```

要点：

- 运行 C# 默认按旧语法兼容理解。
- 涉及 UI、剪贴板、WPF 时，不要依赖 `auto`，应显式指定合适线程模型。
- 不推荐在运行 C# 中直接改普通动作变量；能用步骤输出就用步骤输出。

## 表达式里直接处理引用类型

- 列表、词典、表格这类引用类型，若只是调用成员原地修改，可以直接在 `sys:assign` 的 `$=` 中执行。

```json
{
  "StepRunnerKey": "sys:assign",
  "InputParams": {
    "input": {
      "VarKey": "",
      "Value": "$= {列表}.Add(\"2\")"
    },
    "stopIfFail": {
      "VarKey": "",
      "Value": "1"
    }
  },
  "OutputParams": {
    "output": null
  }
}
```

要点：

- 这是“原地修改引用对象”，不是重新生成新值。
- 仅当表达式足够短、语义清楚时才这样写；复杂逻辑仍应回到内置步骤或拆流程。
