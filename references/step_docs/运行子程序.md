# 运行子程序

- 模块键: `sys:subprogram`
- 步骤类型: `SubProgram`
- 说明: 运行子程序
- 帮助: https://getquicker.net/KC/Help/Doc/subprogram

## 最小 JSON
```json
{
  "StepRunnerKey": "sys:subprogram",
  "InputParams": {
    "subProgram": {
      "VarKey": "",
      "Value": "示例文本"
    },
    "summary": {
      "VarKey": "",
      "Value": "示例文本"
    },
    "skipDebugOutput": {
      "VarKey": "",
      "Value": "false"
    },
    "stopIfFail": {
      "VarKey": "",
      "Value": "true"
    }
  },
  "OutputParams": {
    "isSuccess": "out_isSuccess"
  },
  "IfSteps": []
}
```

## 输入参数
| Key | 名称 | 类型 | 必填 | 默认值 | 取值/可见性 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| subProgram | 子程序 | Text | 是 |  |  | 调用哪个子程序 |
| summary | Summary | Text | 否 |  | 仅用于 NO_SHOW | 内部使用 |
| skipDebugOutput | 跳过调试输出 | Boolean | 否 | false |  | 调试运行动作时，不输出子程序内部调试信息 |
| stopIfFail | 失败后停止 | Boolean | 否 | true |  | 子程序运行失败后是否停止动作 |

## 输出参数
| Key | 名称 | 类型 | 可见性 | 说明 |
| --- | --- | --- | --- | --- |
| isSuccess | 是否成功 | Boolean |  | 子程序是否运行成功 |

## 要点
- 此步骤表示子程序定义体。子步骤列表直接写在 `IfSteps`。
- 复杂动作优先把可复用逻辑拆到顶层 `SubPrograms`。
- 主流程里通过 `sys:subprogram` 调用子程序，减少主 `Steps` 的长度和耦合。
- 子程序名称必须直接表达业务目的，例如“读取配置”“生成选项数据”“统计字数”，不要用“子程序1”“处理逻辑”。
- 如果一段逻辑会被调用两次及以上，默认应抽成子程序。
- 子程序内部仍可继续使用步骤组分阶段。
- `OutputParams.<输出Key>` 的值是变量名字符串，不是对象。
