# 模块和步骤

- 来源：https://getquicker.net/KC/Help/Doc/basic

## 用途

- 用于理解 Quicker 动作是由多个步骤组成的。
- 用于区分步骤是“做什么”的模块能力，不是直接定义顶层动作 JSON 结构。

## 对 qk-action-creator 的直接约束

- 生成步骤时，先确认目标能力对应哪个模块，再去 `references/step_docs/` 查该模块的最小 JSON。
- 不要把“帮助页上的界面概念”直接当成 JSON 字段名。
- 分支、循环、子程序这类结构，必须以对应步骤文档为准，不能只靠基础概念页拼接。
- 先考虑 Quicker 内置模块能不能直接完成需求，再决定是否需要表达式、插值或脚本。
- 如果内置模块已经覆盖目标能力，不要改用 `运行C#代码` 重新实现一遍。
- 复杂动作不要只追求“能跑”，还要按阶段拆开。
- 主流程优先保留“编排层”，把复用逻辑拆进子程序，把阶段逻辑包进步骤组。
- 当一段逻辑会复用、名称明确、边界清楚时，优先用子程序。
- 当一段逻辑只是为了阅读、折叠、整体禁用、整体观察时，优先用步骤组。

## 使用判断

- 用户问“应该用什么模块实现这个需求”时，先看这份文档。
- 用户已经明确要某个步骤 JSON 时，再继续看对应 `step_docs` 文件。
