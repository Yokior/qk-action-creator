# 界面能力选型规则

## 用途

- 这份文档专门回答“该用 `sys:form`、`sys:custompanel` 还是 `sys:customwindow`”。
- 目标是避免把所有交互需求都粗暴归成同一种界面模块。

## 三层能力

### 第一层：`sys:form`

- 用途：
  - 维护参数
  - 编辑配置
  - 结构化输入
- 适合：
  - 表单字段已知
  - 用户是“填写 / 修改值”
  - 保存后即可返回主流程

### 第二层：`sys:custompanel`

- 用途：
  - 提供一组操作入口
  - 做轻量交互面板
  - 做模式选择或快捷操作集合
- 适合：
  - 用户主要是在“点操作项”
  - 需要按钮、菜单、分组
  - 希望动作保持轻交互而不是完整窗口

### 第三层：`sys:customwindow`

- 用途：
  - 复杂展示
  - 强交互
  - 接近独立应用窗口的场景
- 适合：
  - 普通表单或操作窗已经不够表达
  - 需要复杂布局、预览、拖拽、富交互
  - 需要 XAML 级别界面控制

## 单一结论

- 只是维护配置：
  - 用 `sys:form`
- 只是提供一组可点击操作：
  - 用 `sys:custompanel`
- 需要复杂展示与强交互：
  - 用 `sys:customwindow`

## 升级条件

### 从 `form` 升级到 `custompanel`

- 不再是简单填值，而是让用户从多种操作中选择。
- 需要按钮集合、菜单集合、分组操作项。
- 需要“点击后执行”而不是“填写后提交”。

### 从 `custompanel` 升级到 `customwindow`

- 需要复杂布局。
- 需要实时预览。
- 需要拖拽、复杂事件或富展示。
- 操作项已经不足以表达界面需求。

## 降级规则

- 能用 `form` 完成配置维护，就不要先上 `customwindow`。
- 能用 `custompanel` 完成操作集合，就不要先上 `customwindow`。
- 能用 `custompanel` 的 JSON `operationData` 稳定表达，就不要改成更重的窗口方案。

## 对 qk-action-creator 的直接约束

- 用户需求里如果核心动作是“设置参数”，默认先想 `form`。
- 用户需求里如果核心动作是“弹出一组操作项供点击”，默认先想 `custompanel`。
- 用户需求里如果包含“预览、拖拽、复杂布局、独立窗口感”，再考虑 `customwindow`。
- 不要因为想做得“更高级”，默认升级到 `customwindow`。
- 只有普通界面层明显不适合时，才升级界面能力层级。

## 典型结构表现

- 配置维护 + 操作入口并存：
  - 更接近 `form + custompanel`
- 模式选择或操作集合：
  - 更接近 `custompanel`
- 复杂展示、预览、拖拽、强交互：
  - 更接近 `customwindow`
