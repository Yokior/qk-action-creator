# 通知与注释使用规范

## 用途

- 这份文档专门约束 `sys:notify` 与 `sys:comment` 的使用位置。
- 目标是避免动作“能跑但体验差”，或流程结构不清。

## `sys:notify` 什么时候默认应出现

- 配置保存成功后。
- 重要分支命中后。
- 关键失败分支里。
- 用户需要知道动作已经完成时。
- 批处理结束后需要给汇总反馈时。

## `sys:notify` 什么时候不必机械添加

- 每一步都成功就提示一次。
- 纯内部变量流转。
- 用户根本感知不到也不需要感知的小步骤。

## `sys:comment` 什么时候默认应出现

- 主流程进入新阶段时。
- 子程序内部存在两个以上明显阶段时。
- 复杂分支块前。
- 设置入口 / 主功能入口 / 收尾入口之间。

## `sys:comment` 什么时候不必添加

- 只有一两步的小动作。
- 注释内容只是复述步骤名。
- 每一步都加一句没有信息增量的话。

## 推荐通知节点

1. 配置保存成功
2. 关键失败
3. 批处理结束
4. 需要用户继续下一步时

## 推荐注释阶段

1. 初始化默认配置
2. 读取动作状态
3. 判断入口
4. 执行主功能
5. 收尾

## 对 qk-action-creator 的直接约束

- 配置型动作命中设置分支后，默认优先：
  - 保存
  - `sys:notify`
  - `sys:stop`
- 对复杂动作，主流程关键阶段默认应加 `sys:comment`。
- 不要为了凑结构，在每个简单步骤前都插注释。
- `notify` 是交互的一部分，不是装饰。
- `comment` 是结构提示的一部分，不是废话。
