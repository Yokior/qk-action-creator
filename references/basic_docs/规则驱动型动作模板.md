# 规则驱动型动作模板

## 用途

- 这份文档专门处理“先有一组规则，再根据上下文命中后执行”的动作。
- 典型如智能识别、规则分发、条件动作集合、动态菜单生成。

## 适用场景

- 需要根据进程、窗口、网址、文本、剪贴板内容等上下文决定执行路径。
- 规则数量可能增长。
- 后续要维护、排序、启停规则。

## 推荐结构

1. 获取上下文
2. 读取规则集
3. 遍历规则
4. 逐项判定是否命中
5. 命中后进入执行分支
6. 需要时提前 `break`

## 推荐容器结构

- 外层：
  - 列表
- 每条规则：
  - 词典或结构化对象

## 推荐模块组合

- `sys:listOperations`
- `sys:dictOperations`
- `sys:each`
- `sys:simpleIf` / `sys:if`
- `sys:break`
- `sys:subprogram`

## 规则命中后的常见走向

- 直接执行动作
- 生成一组菜单项
- 调用子程序
- 输出结果

## 对 qk-action-creator 的直接约束

- 规则驱动需求里，先设计规则数据结构，再写流程。
- 不要一开始把所有条件判断平铺成连续 `if` 链。
- 命中后如果不需要继续找，优先考虑 `break`。
- 规则项有明确业务语义时，优先下沉执行逻辑到子程序。

## 典型结构表现

- 根据进程、网址、文本、剪贴板等上下文命中规则。
- 命中后直接执行、生成菜单项或调用子程序。
