# 表达式

- 来源：https://getquicker.net/kc/help/doc/expression

## 用途

- 用于理解 Quicker 表达式适合计算值、访问对象成员、做逻辑判断。
- 表达式是 Quicker 动作的核心能力之一，很多轻量逻辑不需要脚本。

## 对 qk-action-creator 的直接约束

- 表达式用于“算出一个值”，不是替代整个步骤 JSON。
- 如果某个参数只是普通文本，不要默认上表达式。
- 如果用户要求条件判断、数值计算、对象成员访问、简单集合处理，优先考虑表达式。
- 表达式写法必须保持为参数值文本的一部分，不额外发明 JSON 字段。
- 只要目标是“把一个计算结果写回变量”，优先考虑 `sys:assign` + `$=`。
- 不要为了 `+1`、减法、布尔判断、成员读取、简单三元选择而默认改用 `sys:csscript`。
- 如果一个模块参数本身就是可输入文本的值，也可以直接把 `$=...` 写进该参数的 `Value`。

## 常用模式

- 变量自增：

```json
{
  "StepRunnerKey": "sys:assign",
  "InputParams": {
    "input": {
      "VarKey": "",
      "Value": "$={次数}+1"
    },
    "stopIfFail": {
      "VarKey": "",
      "Value": "true"
    }
  },
  "OutputParams": {
    "output": "次数"
  }
}
```

- 布尔判断或条件值：
  - `"$={数量}>0"`
  - `"$={状态}==\"完成\"?\"已完成\":\"未完成\""`
- 成员访问：
  - `"$={对象}.Name"`

## 使用判断

- 需求涉及条件、计算、成员访问、集合处理时，先看这份文档。
- 如果同一个需求只是在文本里带变量名，优先回到“文本插值”。
