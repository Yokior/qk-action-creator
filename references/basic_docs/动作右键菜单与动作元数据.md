# 动作右键菜单与动作元数据

## 用途

- 这份文档专门说明“动作右键菜单”和“动作图标”属于哪一层数据。
- 用于避免把 `XAction` 流程 JSON 和 `ActionItem` 动作元数据混写。

## 先分清两层

- `XAction`
  - 负责流程定义。
  - 离线稳定顶层只看：
    - `SubPrograms`
    - `Variables`
    - `Steps`
- `ActionItem`
  - 负责动作本身的元数据。
  - 例如最小 Quicker 版本、触发后是否关闭面板、动作右键菜单。

## 已固化的离线结论

- `XAction` 顶层没有 `ContextMenuData`。
- `ContextMenuData` 属于动作本身的元数据层。
- 动作复制、保存时，这类字段应与动作本体一起处理，而不是并入步骤流程。

## 动作右键菜单字段

- 已确认字段名：
  - `ContextMenuData`
- 所属层级：
  - `ActionItem`
- 不属于：
  - `XAction` 顶层
- 含义：
  - 动作自身的右键菜单定义，不是某个步骤里的菜单。

## 相关动作级字段

- 已确认同层字段至少包括：
  - `MinQuickerVersion`
  - `ContextMenuData`
  - `SkipWhenStopRunningActions`
  - `AllowScrollTrigger`
  - `EnableEvaluateVariable`
  - `DoNotClosePanel`
- 这些字段都应视为动作元数据，不要塞进 `XAction.Steps`。

## 与运行时装饰数据的关系

- 运行时装饰数据层还可能包含：
  - `Icon`
  - `OverlayIcon`
  - `OverlayTooltip`
  - `BadgeText`
  - `BadgeTextColor`
  - `BadgeColor`
  - `ContextMenu`
- 这更像运行时装饰数据，不等于动作定义 JSON 主体。

## 对 qk-action-creator 的直接约束

- 需求如果是“步骤里显示菜单”，优先使用步骤模块：
  - `sys:showmenu`
- 需求如果是“动作本身右键菜单”，不要误写成步骤。
- 用户如果要新做动作右键菜单：
  - 必须先提示用户在 Quicker 中手工创建右键菜单
  - 创建完成后，再根据用户现有菜单继续后续开发
- 在用户尚未手工创建前：
  - 不生成 `ContextMenuData`
  - 不猜菜单语法
  - 不设计整段菜单定义文本
- 生成动作时，如果只输出传统 `XAction` JSON：
  - 不能声称已经完整覆盖 `ContextMenuData`

## 入口参数约定

- 当前工作区已验证：
  - 外部 `runaction:动作ID?参数` 会把参数写入目标动作的 `quicker_in_param`
- 当前工作区样例进一步采用以下约定：
  - 右键菜单项若需要驱动同一动作进入不同分支，优先把菜单项数据当作动作入口参数处理
  - 主流程开头优先判断 `quicker_in_param`
- 这一点在当前工作区里可以稳定固化为本 skill 约定：
  - 若用户已经手工建好右键菜单，并希望流程区分“普通点击”和“菜单入口”，默认优先检查 `quicker_in_param`
- 这一条是当前工作区样例与 skill 约定，不等于已经掌握 `ContextMenuData` 的完整 DSL。

## 右键菜单接续开发规则

- 用户已手工创建右键菜单后，skill 默认只负责后续流程接线，不负责重新定义菜单本体。
- 若右键菜单只是“设置参数”“管理配置”“维护数据”入口：
  - 主流程先判断 `quicker_in_param`
  - 命中后进入设置分支
  - 设置分支完成保存后给短提示
  - 紧接 `sys:stop`
  - 不继续主功能流程

## 为什么必须先手工创建

- `ContextMenuData` 已确认不在 `XAction` 顶层。
- 当前 skill 的主能力是生成和修改 `Data` 中的流程定义。
- 因此动作右键菜单只能作为用户现有动作元数据来接续修改，不能作为全新离线菜单定义直接生成。

## 注入前提

- 当前 `SKILL.md` 里的注入器约定是：
  - 读取 JSON
  - 反序列化为 `XAction`
  - 写回目标动作
- 这条链路只覆盖流程数据。
- 所以即使知道 `ContextMenuData` 属于动作元数据，也不能把它当成当前 skill 的默认可生成目标。

## 可稳定固化的结论

- 可以固化：
  - `ContextMenuData` 是动作级字段
  - `XAction` 顶层不含该字段
  - 新建动作右键菜单时，应先让用户手工创建
  - 后续开发应基于用户现有菜单继续修改
- 不能在当前 skill 里擅自固化：
  - 动作右键菜单文本语法的完整 DSL
  - 动作右键菜单 JSON 结构的完整公开模型
- 这些细节在现有工作区里没有稳定、完整、可直接复用的离线公开定义，不能猜。
